# Design decisions

Where the spec was ambiguous or silent, the simpler option was chosen and recorded here (spec section 15).
Changes to `AlgoPlatform.Sdk` are marked **SDK**.

| # | Decision | Why |
|---|---|---|
| D-01 | Target **.NET 8** (`net8.0`, LTS). The machine has SDK 9 with the .NET 8 runtime installed. | Spec asks for .NET 8 or the latest LTS; .NET 9 is STS. |
| D-02 | The strategy engine (`StrategyEngine`, the `IStrategyContext` implementation) lives in `AlgoPlatform.Host`; `Replay`, `ControlPlane` and the tests reference the Host project. | The spec's project list has no engine library. Live and replay must run the *same* engine code, so it lives in one place. |
| D-03 | **SDK**: `OrdStatus.PendingNew` appended (value 8). Existing values unchanged. | Spec 8.3 says the OMS records `PendingNew`, but the enum in section 7 lacked it. |
| D-04 | **SDK** additions: `IStrategyContext.Instruments` and `GetParameter(name, default)`; `IReferenceData.TryGetBySymbol`; `Tick.IsTrade`; `Price` (fixed-point helpers), `RejectCodes`, `StrategyBase`; the SDK's own `LogLevel` enum. | A strategy needs its manifest instruments and parameters without touching files (FR-1), and a symbol lookup; the SDK must have no dependencies, so no `Microsoft.Extensions.Logging`. |
| D-05 | `ctx.NowNs` is the **timestamp of the event being handled**, not "now". | Determinism (FR-9): the strategy's notion of time comes from the journal, so replay sees the same values. Wall/monotonic time is used only for metrics. |
| D-06 | Inputs are journalled **on the loop thread at dequeue**, into a per-strategy SPSC journal ring drained by one journal thread into a per-strategy memory-mapped file. Sequence numbers are still stamped at the host boundary (feed handler, gateway, host). | With conflation, each strategy sees a different subset of market data. Journalling at dequeue records exactly what that strategy saw, which is what replay needs. A full journal ring makes the loop spin (counted as a stall) rather than drop: a lossy journal would break replay. |
| D-07 | Decisions the loop takes for timing reasons are **injected as events** and journalled: timer firings, handler-budget kills (`MarkSlow`), watchdog kills, async results. Events the loop derives deterministically (a local risk reject of a `Replace`) are flagged `Internal` and not journalled, because replay regenerates them. Internal events are processed immediately after the event that caused them, in live and replay alike. | This is what makes "byte-for-byte identical outputs" achievable with real threads and real timing. |
| D-08 | ExecId de-duplication is **per order with a high-water mark** (`ExecId <= LastExecId` is a duplicate), in both the OMS and the gateway. It assumes exchange ExecIds increase within a session, which the simulator guarantees. | A global ExecId set grows without bound and allocates on the loop thread (it failed the zero-allocation test). Fills are also accounted by `CumQty` delta, so even a duplicate without an ExecId cannot double count. |
| D-09 | If the gateway's outbound ring is full, `Submit` **spins** instead of rejecting. | A reject that depends on how fast the gateway thread drains would be non-reproducible. Spinning is visible in metrics (`RingOrderSink.Stalls`). |
| D-10 | Gateway recovery: the gateway **never re-sends orders**. The exchange's resend request is answered with a GapFill. Missed inbound messages are re-requested with `35=2`. Open orders are then reconciled with an **order status request (`35=H`)**, a message type the spec's list lacks. Tags added: 49/56 (comp ids), 41 (OrigClOrdID), 103 (OrdRejReason), 434, 98, 7/16/36/123. An order the exchange does not know is marked `Rejected` with `UnknownAtExchange`. Commands received while the session is not Up are answered locally (`ExchangeDown`). A killed strategy re-issues its cancels when the exchange comes back. | "State is rebuilt from exchange reports, never guessed" (FR-7). Re-sending a new order risks a duplicate; asking the exchange whether it has it does not. |
| D-11 | A Replace keeps the order id: `11 = 41 = OrderId`. | Simpler than ClOrdID chains, and the strategy-facing API (`Replace(orderId, ...)`) already keeps the id. Real FIX venues need a new ClOrdID per replace; that is a gateway-adapter concern. |
| D-12 | Run modes: **Live** connects the gateway to an external SimExchange over TCP. **Paper** starts an embedded SimExchange on loopback whose quotes are driven by the host's own feed (via a market-data tap). **Replay** has two forms in `AlgoPlatform.Replay`: `JournalReplayer` (FR-9, exact re-feed of a journal) and `BacktestRunner` (goal 3: recorded or synthetic ticks plus an in-process matcher on a virtual clock). | v1 has no real exchange (non-goal), and Paper must fill against the same prices the strategy sees. |
| D-13 | The isolation acceptance test allows the sibling's p99 to rise by 20% **plus 2 µs** of absolute slack. | The clock resolution is 100 ns on this Windows box, and run-to-run noise at a 10 µs p99 is around 1 µs. Without the slack the test is flaky. Observed: 10.2 µs alone, 9.7 µs next to the sleeper. |
| D-14 | Feed-gap recovery takes the snapshot synchronously from the simulator. The instrument is marked stale and then recovered, both as journalled `InstrumentStatus` events. | A real feed would request the snapshot asynchronously; the stale and recovered events and the risk behaviour stay the same. |
| D-15 | Conflation keeps **per-instrument** ordering: a pending quote is moved ahead of a later trade on the same instrument. Order *across* instruments can change while a subscriber is being conflated. | Latest-value semantics are per instrument (FR-3). Ordering across instruments would require queueing everything, which defeats conflation. |
| D-16 | The per-strategy (gross) position limit is conservative: the sum of \|positions\| plus *all* working quantity, on both sides. Default is `maxPosition * instruments`; set `maxGrossPosition` to override. | "Max position per strategy" is undefined in the spec. Worst-case exposure is the safe reading. |
| D-17 | `HostEvent` uses explicit layout: `Tick` and `ExecutionReport` share storage. | It is copied once per subscriber on fan-out. Shrinking it raised fan-out to 50 subscribers by about 44% in an isolated measurement. |
| D-18 | The watchdog **cannot abort** a hung loop thread (.NET has no thread abort). It detaches the strategy's market data, has the gateway block the strategy and cancel its open orders (`CancelAllForStrategy`), raises an alert, and posts `MarkSlow`. The host has to be restarted to reclaim the thread. | That is the limit of in-process isolation, and why the spec puts untrusted code on separate sandbox hosts. |
| D-19 | "Host crash: restart in recover mode" is only partly built. The control plane detects missed heartbeats, marks the host Down and raises an alert. There is no process supervisor in v1, and a restarted host reconciles through the normal gateway logon path. | A process supervisor (systemd, k8s, or a Windows service) is deployment infrastructure. |
| D-20 | **Kill** keeps strategy callbacks running: it cancels working orders, and `Submit` then returns `KillSwitch`. **Slow** (`MarkSlow`) and **Faulted** stop callbacks and detach market data. | A killed strategy may still want to log or observe. A slow or faulted one must stop consuming resources. |
| D-21 | The rate limiter counts new orders and replaces in a sliding one-second window on event time. Cancels are never rate-limited. | Cancels only reduce risk, and the kill switch depends on them. Event time keeps the limiter reproducible. |
| D-22 | Thread pinning is **off by default** (tests, laptops). Hosts take an explicit `Cores` list: the first two go to the feed handler and the gateway, the rest to strategy loops. No NUMA discovery. | Pinning without isolated cores on a desktop OS made latency worse in practice. The interface (`IThreadAffinity`) and the Windows and Linux implementations are in place. |
| D-23 | Market orders use the last mid for notional. `KillAndFlatten` sends market IOC orders that bypass limits but still need the exchange to be up. | Flattening only reduces risk. |
| D-24 | The OMS removes terminal orders by default (`RetainTerminalOrders = false`); tests and audits can retain them. | Bounded memory on a long-running loop. |
| D-25 | ReadyToRun is not configured (it needs a RID-specific publish), and the host does not refuse live data until it is warm. The benchmark harness has an explicit warm-up phase. | Listed as a known gap in PROGRESS.md. |
| D-26 | The SimExchange keeps one persistent session per SenderCompID across TCP connections and stores every outbound message for resend. It uses locks and allocates freely. | It is a test fixture, not part of the hot path. Note that it runs in-process in Paper mode, and its allocations cause GCs that show up in Paper-mode tail latency (PERFORMANCE.md). |
